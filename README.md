## 🚀 Featured Project — Pishro Clinic

One of my main projects is **Pishro Clinic**, a production-oriented digital platform for psychological services and assessment.

The platform covers much more than a typical website:

* 👨‍⚕️ Psychologist profiles and service discovery
* 📅 Appointment and booking workflows
* 🔐 OTP authentication and session management
* 🔄 Access & refresh token architecture
* 💳 Payment and wallet/settlement workflows
* 🧪 Online psychological and cognitive assessments
* 📊 Structured assessment results
* 📄 User and psychologist-oriented reports
* 🧠 Assessment attempt and result architecture
* 🔎 SEO and structured data
* 🗄️ MongoDB-backed transactional workflows
* ⚡ Redis-based infrastructure
* 📦 Background jobs and scheduled tasks
* 🐳 Dockerized services
* 🌐 Production deployment and reverse proxy configuration
* 🔐 Production security and server hardening

The project has given me hands-on experience with the parts of software engineering that don't usually appear in tutorials:

> **authentication edge cases, failed transactions, production incidents, backups, infrastructure, security, deployment, observability, and keeping the damn thing alive after users start using it.**

## 🧩 How I Build Software

My approach is generally:

```text
Understand the problem
        ↓
Define the domain
        ↓
Design the architecture
        ↓
Build the API / backend
        ↓
Build the frontend
        ↓
Integrate infrastructure
        ↓
Test real-world edge cases
        ↓
Deploy
        ↓
Monitor
        ↓
Fix what production teaches you
```

I prefer **simple systems with clear boundaries** over unnecessary abstraction.

Good architecture, in my opinion, should make the next change easier — not make the codebase look impressive during a PowerPoint presentation.
